# N7：大型語言模型推論每次查詢的能耗估計為什麼差異很大？有哪些提升能源效率的途徑？

## 結論摘要
大型語言模型（LLM）推論每次查詢的能耗估計差異極大（公開報告差距超過一個數量級），主因在於真實世界的推論高度受工作負載幾何形狀、軟體堆疊、硬體加速器、輸入輸出 Token 分布以及批次大小等因素影響，導致僅依賴浮點運算次數（FLOPs）或理論 GPU 利用率的估算嚴重低估實際能耗 [KB-1][OA-1][OA-2]。提升能源效率的途徑涵蓋使用小型語言模型（SLM）或傳統自然語言處理技術、模型量化（如 H100 上的 FP8 提升 TPS）、最佳化批次大小與解碼策略、動態調整計算資源（如調整模型層與精度級別），以及推動終端用戶的需求回應與透明化能耗計量 [KB-2][KB-5][OA-1][OA-2][OA-4][OA-5]。

## 證據分析
*   **能耗估計差異大的原因**：
    *   公開的「每次查詢能耗」報告差異超過一個數量級 [KB-1]。
    *   推論優化與能耗高度敏感於工作負載幾何形狀（workload geometry）、軟體堆疊（software stack）與硬體加速器（hardware accelerators） [OA-1][OA-2]。
    *   基於 FLOPs 或理論 GPU 利用率的單純估算會顯著低估實際能耗，因為其忽略了多樣化的真實世界推論工作負載、輸入輸出 Token 分布及批次大小的變異 [OA-1][OA-2]。
    *   推論能耗與輸出 Token 長度及回應時間高度相關 [OA-4]。
*   **提升能源效率的途徑**：
    *   **模型與技術選擇**：針對數學、程式碼等 Token 密集任務，小於 1000 億參數的小型語言模型（SLM）可比大模型降低 1 到 2 個數量級的能量；傳統自然語言處理技術（如文字分類）亦可比 LLM 降低數個數量級的能量 [KB-5]。LLM 推論效率低落的主因包含模型規模大、具二次複雜度的 Attention 運作，以及自動迴歸解碼方式 [OA-3]。
    *   **模型量化與硬體應用**：模型量化（如 H100 上的 FP8 相較於 FP16 可提供約 1.4 至 2.4 倍的 TPS）與新興低位元量化技術能有效降低能耗 [KB-5][OA-4]。
    *   **系統與運行優化**：透過軟體框架、解碼策略、GPU 架構、線上與離線服務設定及模型並行配置進行優化 [OA-1][OA-2]。最佳批次大小與目標提示詞（prompts）也能顯著減少能源使用 [OA-4]。
    *   **動態計算與隨選調整**：透過動態調整模型層、注意力頭與精度級別等適應性推論時間計算框架，在維持效能的同時降低能耗 [OA-5]。
    *   **用戶端與管理機制**：提供透明的能源或碳排指標、能效標籤、每次查詢預估能耗、計價誘因、延遲處理折扣（針對非緊急任務），以及善用用戶需求的彈性（如不需要立即回應的查詢）來支援節能 [KB-2]。

## 限制與建議
*   **證據侷限**：現有文獻多數透過特定模型、任務、提示詞或模擬框架進行基準測試與效能建模，不同研究之間的硬體環境、批次大小設定與任務複雜度存在差異，且部分研究強調其實驗針對特定情境與幾何形狀 [OA-1][OA-2][OA-4]。
*   **後續建議**：建議未來針對標準化工作負載（統一輸入輸出 Token 分布與硬體條件）進行跨平台實測，並進一步探討用戶端延遲彈性與資料中心動態調配結合時的實際節能成效 [KB-2][OA-1]。
